# NIX ESOTERICA

- Use `lib.attrValues { inherit (pkgs) foo bar; }` or explicit `[ pkgs.foo pkgs.bar ]` instead of `with pkgs;`
- `attrValues` sorts alphabetically by attr name, not source order — use explicit lists when order matters
- Don't add `flake-utils` — use `lib.genAttrs` or `flake-parts` when justified
- Don't use `<nixpkgs>` lookup paths — use flake inputs or pinned sources
- Avoid `rec` — use `let` instead
- When importing nixpkgs manually, always set `system`, `config`, `overlays` explicitly
- Keep `specialArgs` narrow — don't pass all `inputs`
- Prefer module options over hidden function args for repo policy
- Use `mkDefault`/`mkForce`/`mkBefore`/`mkAfter` only when priority/ordering is intentional
- Keep `imports` static and near the top — no conditional imports
- Use `callPackage` for local packages
- Use smallest override: `.override` > `.overrideAttrs` > overlay — avoid `overrideDerivation`
- Overlays are for package-set-wide changes, not one-off tweaks
- Pin inputs (`flake.lock`, `npins`) — no floating branches or bare `fetchTarball`
- Name local source paths so store path doesn't depend on checkout dir name
- Separate system pkgs (`environment.systemPackages`) from user pkgs (`home.packages`)
- Don't bump `stateVersion` casually — read release notes first
- Prefer structured `settings` options over raw text files and ad-hoc shell scripts
- Use `allowUnfreePredicate` over broad `allowUnfree = true`
- Keep flake outputs standard (`nixosConfigurations`, `homeConfigurations`, `devShells`, `formatter`)
- Use `follows` deliberately — check if upstream expects its own pinned nixpkgs
- Keep supported systems list visible, not hidden in `eachDefaultSystem`
- Comments explain why, not what
- In overlays: `prev` = original, `final` = fixed-point including overlay changes
- Validate with `nix flake check` and `statix`
- Prefer clarity and explicit data flow over cleverness
